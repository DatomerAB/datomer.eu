# Pär v0.1.9-beta.2026100201

## What’s new in Pär v0.1.9-beta.2026100201

Cross-platform groundwork. macOS behaviour is unchanged; the work here makes
Windows viable and prepares the same paths for Linux.

### Fixed

- **Vault key no longer written in plaintext on Windows.** `keyring`'s Credential
  Manager backend needs `pywin32-ctypes`, which was never declared as a
  dependency, so the backend failed to load and the key fell back to a file on
  disk — which was then preferred over the credential store on every later load.
  The dependency is now declared and bundled, Windows prefers the credential
  store, and any existing plaintext mirror is migrated into it and deleted.
- **External links and Act routines on Windows and Linux.** Opening a URL shelled
  out to macOS `open`, and script execution to `zsh`, so both failed outside
  macOS.
- **Stale backend processes on Windows.** Cleanup was macOS-only behind a stub
  that silently did nothing, so a crashed app left the backend holding port 7433
  and the next launch failed with a misleading profile error.
- **Model deletion on Windows.** Windows refuses to unlink an open file, so
  deleting a loaded model failed. The model is now unloaded first, and a genuine
  lock reports a clear conflict instead of a server error.
- **Console windows no longer flash** on Windows when the backend shells out to
  system tools.

### Added

- **Diagnostic logging on every platform.** No logger was registered at all, so
  backend startup messages were discarded. Logs now rotate to
  `~/Library/Logs/com.par.desktop/par.log` on macOS,
  `%LOCALAPPDATA%\com.par.desktop\logs\par.log` on Windows, and the XDG data
  directory on Linux, opening with a banner naming version, platform, port and
  resolved backend path, and recording the last lines of output before an exit.
- **A real failure screen when the backend doesn't start**, showing the log path
  and an *Open logs folder* button, replacing a misleading "Could not save
  profile" message during setup.
- **Secret files are hardened per platform** — POSIX mode bits as before, and on
  Windows an explicit ACL plus DPAPI wrapping, so a copied or cloud-synced file
  is useless on another machine. A warning is logged if the vault sits inside a
  cloud-synced folder.
- **Windows installer now requires the Visual C++ 2015-2022 runtime**, offering
  to install it. Without it the backend died on launch with no visible error.
- **Windows CI**: a `windows-latest` job running the platform-sensitive tests,
  and a build-time smoke test that starts the packaged backend and fails the
  build if it never answers `/health`.

### Changed

- Platform-specific process, shell and file-manager code moved into a single
  `platform` module with a real implementation per OS, replacing stubs that
  silently did nothing.
- Backend readiness wait raised to 180s on Windows, where Defender scans the
  extracted bundle on first launch.
- Get Started guides document Windows installation, including the security
  prompts an unsigned beta triggers.
